# Общий контекст для агентов технического аудита

> Читай целиком перед работой. Правила ниже обязательны.

## Роль аудита

Технический аудит кодовой базы HeatCalc для владельца-одиночки. Заказчик — Principal Engineer,
приглашённый со стороны. Цель — исполнимый план, приоритизированный по деньгам и рискам.

## ГЛАВНОЕ ОГРАНИЧЕНИЕ

Проект написан **одним человеком за два месяца**, он **работает**, задеплоен, команды у автора нет.

- **Запрещено рекомендовать переписывание ради красоты.** «Вынести в микросервис», «перейти на TS
  целиком», «внедрить DDD», «заменить Express» — не выводы аудита. Допустимо только с расчётом
  окупаемости и только если без этого проект физически не движется.
- **Каждая находка обязана иметь цену и выгоду**: что не так → конкретный сценарий отказа (не
  «плохая практика») → стоимость починки в часах/днях → что будет, если не чинить никогда.
- **Категории приоритета** (две вехи владельца: A — выпустить на живых монтажников, B — брать деньги):
  `БЛОКЕР-A`, `БЛОКЕР-B`, `ДОЛГ` (мешает развитию, не блокирует), `КОСМЕТИКА` (записать и забыть).
- **Отдельная обязательная категория — «НЕ ТРОГАТЬ»**: места, которые выглядят неправильно, но
  чинить их сейчас не надо (работает, риск правки выше выгоды). Это такой же результат, как проблемы.

Плохой аудит выдаёт 200 замечаний и парализует. Хороший — 15 вещей, которые надо сделать,
и явно снимает вину за остальные 185.

6. **Язык — русский.** Идентификаторы и термины — как в коде.
7. **Уважай сделанное хорошо.** В каждом отчёте — секция «Сильные стороны» с примерами и якорями.
8. **READ-ONLY по продуктовому коду.** Ничего не рефакторить, не удалять, не «чинить по пути».

## ФАКТУРА ПРОЕКТА (проверено оркестратором, перепроверяй перед выводами)

**Что это.** B2B/B2C сервис инженерного подбора отопления: анкета → климат → теплопотери → ГВС →
подбор оборудования → гидравлика → JSON-отчёт → коммерческая смета → PDF → публичная share-ссылка.
Демо: `https://heatcalc-mp62.vercel.app`, API: `https://heatcalc-api-mp62.onrender.com`.

**Стек.** Монорепо: `backend/` (Express, ESM, **JS + JSDoc + `checkJs`**, не TS), `frontend/`
(React 19 + Vite + TS + React Query + react-router), `shared/` (контракты BE↔FE),
`components/schemas/` + `openapi.yaml` (25 путей), `e2e/` (Playwright), `scripts/` (root verify).
MongoDB/Mongoose. Auth — Clerk (frontend SDK) + JWKS через `jose` на backend. PDF — Puppeteer/Chromium.
Деплой: Vercel (frontend) + Render free (backend, сон, cold start 30–50 с).

**Масштаб.** ~63 000 строк, 513 файлов исходников, 1033 файла в git. 126 коммитов,
16.06.2026 → 23.08.2026, один автор. Ветка аудита: `qa/audit-and-persona-suite`.

**Расчётный пайплайн.** `backend/src/api/runCalculation.js` → `getReferenceBundle()` →
`toCalcRuntimeContext()` → `validateAndNormalizeInput` (AJV) → `buildReport({ input, ctx })`.
Внутри: климат → `logic/heatlossByRooms.js` → `logic/hotWater.js` → `matching/*` → `hydraulics/*`
→ `recommendations/*` → `report/buildFinancialBom.js`.

**Заявленные правила (проверить, что соблюдаются в коде, а не только в доках).**
