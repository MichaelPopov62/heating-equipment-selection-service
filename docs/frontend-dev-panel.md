# Frontend: панель разработчика DevPanel

Документ предназначен для разработчиков, которые отлаживают анкету, расчёт, сохранение проекта и публичные ссылки во frontend.

## Когда отображается панель

Кнопка **`Dev`** открывает панель разработчика:

| Среда | Условие |
|-------|---------|
| **`npm run dev`** (localhost) | всегда (команда разработки) |
| **Hosted staging** | admin (`GET /api/v1/me` → `role=admin`) и флаги окружения — см. [`deploy/environments.md`](deploy/environments.md) |
| **Hosted production** | **никогда** |

Обычному пользователю и пользователю без `role=admin` на staging DevPanel не показывается.

`POST /api/v1/projects/import` на backend — **только admin** (`403 ADMIN_REQUIRED` для `role=user`).

Справа внизу также может отображаться отдельная кнопка **React Query Devtools**. Она открывает инспектор запросов и кэша TanStack React Query и доступна только в режиме разработки Vite. Флаг `VITE_DEV_TOOLS=1` сам по себе React Query Devtools не включает.

### Где в UI монтируется кнопка Dev

Кнопка **Dev** появляется **только в режиме анкеты** (`bootstrapMode === 'survey'`, компонент `SurveyAppRoot`):

- после «Почати новий розрахунок»;
- после открытия или импорта проекта;
- после восстановления черновика из hash / localStorage (сразу переход в `survey`).

На **стартовом экране** (`StartAppRoot`: `start`, `resolving`, `error`) DevPanel **намеренно не монтируется** — cold path остаётся лёгким, без `useSurveyProject` и lazy-chunk DevPanel.

На localhost в `npm run dev` на стартовом экране справа внизу может быть только **React Query Devtools** (иконка TanStack); это не кнопка **Dev**.

## Быстрая шпаргалка «что нажать в какой ситуации»

1. Сохранить черновик локально → **`Зберегти JSON`**.
2. Экспорт проекта для переноса между базами → **`📥 Експорт (Save JSON)`** (требует `projectId` для полной истории расчётов).
3. Загрузить черновик с диска (только UI) → **`Відкрити JSON`**.
4. Импорт проекта в текущую MongoDB → **`📤 Імпорт (Load JSON)`**.
5. Сохранить проект в MongoDB без расчёта → **`На сервер`**.
5. Сохранить проект и, если анкета готова, получить расчёт → **`На сервер + розрахунок`**.
6. Пересчитать вручную без сохранения проекта → **`POST /api/v1/calc`**.
7. Посмотреть запрос, сформированный для расчёта → **`CalcInput`**.
8. Посмотреть полный результат расчёта → **`Report`**.
9. Посмотреть основные блоки результата → **`Модули`**.
10. Скачать краткую текстовую сводку → **`TXT зведення`**.
11. Передать черновик через legacy hash-ссылку без сервера → **`Hash #survey=`**.
12. Закрыть ранее опубликованную клиентскую ссылку → **`Відкликати share`**.

## Доступность действий

DevPanel доступен **только в режиме анкеты** (`SurveyAppRoot`). Все перечисленные ниже действия выполняются в контексте открытой сессии анкеты:

- **`Відкрити JSON`**, **`📤 Імпорт (Load JSON)`** — загрузка черновика или bundle; после успеха сессия остаётся в `survey`.
- **`Зберегти JSON`**, **`📥 Експорт (Save JSON)`**, **`На сервер`**, **`На сервер + розрахунок`**, **`TXT зведення`**, **`Hash #survey=`** — требуют активной анкеты.
- **`POST /api/v1/calc`** — только когда сессия разрешает расчёт и анкета готова.
- Кнопки просмотра JSON (**Draft**, **CalcInput**, **Report**, **Модули**) — данные текущей сессии.
- **`Відкликати share`** — требует существующий `projectId`.

В верхней части панели выводится **Project id** — идентификатор проекта на сервере. Если проект ещё не был сохранён или загружен с сервера, показывается `—`.

## Действия с файлами и сервером

### `Відкрити JSON`

Открывает системный диалог выбора `.json`-файла, разбирает файл как SurveyDraft, применяет миграции совместимости и загружает черновик в сессию.

Используйте действие, чтобы:

- восстановить локально сохранённый черновик;
- проверить чтение и миграцию SurveyDraft.

Перенос проекта между окружениями (Production ↔ Staging) — через **`📥 Експорт`** / **`📤 Імпорт`** (см. [`project-export-import.md`](project-export-import.md)).

Некорректный JSON или данные, не соответствующие поддерживаемому формату SurveyDraft, не применяются; текст ошибки отображается в интерфейсе.

### `Зберегти JSON`

Собирает текущий SurveyDraft и скачивает его в файл:

```text
heatcalc-{clientName}-{YYYY-MM-DD}.json
```

Недопустимые для имени файла символы в имени клиента заменяются символом `_`, а имя ограничивается 40 символами. Если имя клиента не заполнено, в SurveyDraft используется значение `Без имени`.

Действие предназначено для локальной резервной копии и передачи редактируемого черновика. Оно не записывает проект в MongoDB.

### `📥 Експорт (Save JSON)`

Dev-экспорт для переноса между Production / Staging:

1. Если есть **`projectId`** — запрашивает проект и **полную историю** `calculations` с API (или из React Query cache, если список уже полный).
2. Merge анкеты: локальная сессия имеет приоритет над `project.survey` с сервера.
3. Формирует **`ProjectExportBundle`** (`exportSchemaVersion: 1`) без Mongo `_id`, `shareToken`, `survey.projectId`.
4. Скачивает `project-export-{clientName}-{date}.json`.

Без `projectId` — fallback: только локальная сессия + предупреждение (история расчётов с сервера недоступна).

Требует JWT для server export. Кнопка **`Зберегти JSON`** не изменяется.

### `📤 Імпорт (Load JSON)`

Dev-импорт в **текущую** MongoDB backend (к какому API привязан frontend):

1. Выбор `.json` — `ProjectExportBundle` или legacy SurveyDraft.
2. `POST /api/v1/projects/import` (JWT обязателен).
3. Новый `projectId` в целевой базе; UI загружает survey + последний report из файла.
4. Сообщение: «Проект успішно імпортовано!».

Отличие от **`Відкрити JSON`**: импорт **записывает** проект на сервер; «Відкрити JSON» только меняет локальную сессию.

Подробнее: [`project-export-import.md`](project-export-import.md).

### `На сервер`

Создаёт новый проект либо обновляет существующий и сохраняет SurveyDraft в MongoDB. Расчёт не запускается.

Требования:

- приложение находится в режиме анкеты;
- заполнено имя клиента;
- пользователь авторизован для работы с Projects API;
- backend и MongoDB доступны.

После первого успешного сохранения DevPanel показывает полученный `projectId`.

### `На сервер + розрахунок`

Сначала создаёт или обновляет проект. Если анкета готова к расчёту, затем отправляет `calcInput` и SurveyDraft на:

```text
POST /api/v1/projects/{projectId}/calc
```

Полученный отчёт записывается в текущую сессию.

Если анкета не готова к расчёту, проект всё равно сохраняется, но запрос расчёта не выполняется. Интерфейс сообщает: `Проєкт збережено (розрахунок пропущено — неповна анкета)`.

Требования совпадают с действием **`На сервер`**. Для выполнения расчёта дополнительно должны выполняться условия готовности анкеты.

### `TXT зведення`

Скачивает файл `heatcalc-{clientName}-summary.txt` с краткой сводкой:

- клиент;
- тип объекта, количество этажей и помещений;
- внутренняя и наружная температуры;
- дата сохранения;
- теплопотери, требуемая мощность и модель котла — если эти данные есть в последнем отчёте;
- количество предупреждений — если они есть в последнем отчёте.

TXT предназначен для краткого обмена информацией. Он не заменяет SurveyDraft JSON, полный отчёт или PDF-смету.

### `Hash #survey=`

Удаляет `lastCalcReport` из копии SurveyDraft, кодирует оставшийся черновик в URL вида `#survey=...` и копирует URL в буфер обмена.

Это legacy/dev-механизм передачи черновика:

- сервер и MongoDB для создания ссылки не используются;
- ссылка содержит данные анкеты, но не содержит расчётный отчёт;
- при открытии ссылка восстанавливает редактируемый SurveyDraft;
- декодер отклоняет JSON размером более 51 200 символов, поэтому механизм подходит только для небольших черновиков;
- если браузер не предоставляет Clipboard API, копирование завершается ошибкой.

Не путайте hash-ссылку с клиентской публичной ссылкой `/s/{shareToken}`. Публичная ссылка создаётся через Projects API, хранит серверный snapshot и открывает read-only презентацию.

### `POST /api/v1/calc`

Запускает немедленный ручной расчёт через:

```text
POST /api/v1/calc
```

Действие сбрасывает frontend-dedup расчёта и выполняет запрос без ожидания debounce. Полученный отчёт записывается в текущую SurveySession.

Ручной расчёт:

- не создаёт и не обновляет проект;
- не сохраняет результат в MongoDB как расчёт проекта;
- предназначен для проверки calc payload, ответа backend и принудительного пересчёта.

Кнопка отключена, пока анкета не готова к расчёту. Текущие frontend-условия готовности:

1. Добавлено хотя бы одно помещение.
2. У каждого помещения заданы положительные площадь и высота.
3. Хотя бы у одного помещения есть один из источников теплопотерь:
   - положительная площадь наружной стены;
   - положительная площадь кровли при верхней границе `roof`;
   - положительная площадь потолка при верхней границе `unheated`;
   - окно с положительными шириной и высотой проёма.
4. Расчёт разрешён текущим состоянием SurveySession.

Готовность кнопки означает, что frontend может сформировать запрос. Окончательную проверку контракта выполняет backend.

### `Відкликати share`

Отправляет запрос:

```text
DELETE /api/v1/projects/{projectId}/share
```

Запрос аннулирует ранее опубликованный `shareToken`; клиентская ссылка `/s/{shareToken}` перестаёт предоставлять доступ к презентации. Локальный `publicPath` после успешного ответа очищается.

Действие требует авторизации, доступного backend и существующего `projectId`. Если `projectId` отсутствует, интерфейс показывает `Немає projectId`.

## Просмотр JSON

Кнопки нижнего ряда не скачивают и не отправляют данные. Они сериализуют выбранное значение и показывают его в блоке под кнопками.

### `Draft JSON`

Показывает полный SurveyDraft, собранный из текущей сессии. В него входят поля анкеты, `clientName`, опциональный `projectId`, служебные поля формата черновика и `lastCalcReport`, если отчёт присутствует.

Используйте этот режим для проверки сохраняемого черновика и сравнения состояния до и после миграций или изменений формы.

### `CalcInput`

Показывает payload, который frontend формирует для `POST /api/v1/calc` и расчёта проекта.

Это не копия SurveyDraft: builder преобразует состояние формы в контракт CalcInput. Режим полезен для анализа ошибок валидации `400` и проверки enum, размеров, температур и других входных полей.

Просмотр CalcInput сам по себе не отправляет запрос.

### `Report`

Показывает полный `calcReport`, находящийся в SurveySession. Это последний отчёт, полученный автоматическим, ручным или проектным расчётом либо загруженный вместе с проектом.

Если отчёта нет, отображается `null`.

### `Модули`

Показывает сокращённый объект из пяти верхнеуровневых частей текущего отчёта:

- `commercial` — финансовая смета;
- `matching` — подбор оборудования;
- `calculations` — расчётные результаты;
- `meta` — метаданные отчёта и источников справочников;
- `warnings` — общие предупреждения.

Если отчёта или отдельного блока нет, соответствующее значение отображается как `null`.

### `Закрити`

Закрывает DevPanel и сбрасывает выбранный режим просмотра JSON. Данные анкеты и расчёта при этом не изменяются.

## Отличие способов расчёта

- **`POST /api/v1/calc`** — немедленный расчёт без сохранения проекта.
- **`На сервер`** — сохранение проекта без расчёта.
- **`На сервер + розрахунок`** — сохранение проекта и последующий проектный расчёт, если анкета готова.
- Автоматический расчёт SurveySession — основной механизм frontend; он запускается после подходящих изменений анкеты с debounce и dedup.
