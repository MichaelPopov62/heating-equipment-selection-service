## ГЛАВНАЯ НАХОДКА: воспроизведение сценария «форму заполнил, расчёт не получил»

**Сценарий воспроизведён полностью и надёжно.** Он воспроизводится не на экзотике, а на самом естественном пути пользователя.

### Рецепт (проверен дважды, воспроизводится 100%)

1. Открыть https://heatcalc-mp62.vercel.app, нажать «Зрозуміло» в cookie-баннере, нажать «Почати новий розрахунок».
2. Шаг «Об'єкт»: в поле «Кількість приміщень (1…50)» поставить `3`. Больше ничего не трогать.
3. Шаг «Приміщення»: раскрыть каждую из трёх карточек и заполнить **то, что выглядит обязательным**:
   - Приміщення 1: «Назва» = `Вітальня`, «Площа, м²» = `28`
   - Приміщення 2: «Назва» = `Спальня`, «Площа, м²» = `16`
   - Приміщення 3: «Назва» = `Санвузол`, «Тип» = `Санітарний вузол`, «Площа, м²» = `6`
4. Шаг «Гаряча вода»: «Кількість осіб» = `4`.
5. Остальные шаги («Тепла підлога», «Котел», «Радіатори», «Водонагрівач», «Гідравліка») оставить по умолчанию — там везде уже выбраны валидные значения.
6. Перейти на «Результат технічний».

### Что видит пользователь

- На «Результат технічний» — крошечная таблица из четырёх строк:
  «Загальна площа приміщень 50.0 м² / Потужність приміщень 5.0 кВт / Запас (15%) 0.8 кВт / Разом за теплом 5.8 кВт»
  и подпись «**Джерело: швидка оцінка (100 Вт/м²)**».
- **Нет ни котла, ни радиаторов, ни гидравлики, ни водонагревателя, ни цен.**
- На «Підсумок фінансовий» — «**Немає актуальної кошторису. Заповніть анкету та дочекайтеся розрахунку.**»
- **Ни одного сообщения об ошибке. Ни одного маркера незаполненного поля. Ни одной подсказки, чего не хватает.**
- Скриншоты: `u3-MAIN-repro-no-calc-quick-estimate.jpg`, `u3-MAIN-repro-financial-empty.jpg`

### Что происходит технически

`browser_network_requests` после шага 6: **ни одного `POST /api/v1/calc` не было отправлено вообще**. Клиент молча не считает нужным звать сервер. Всё, что видит пользователь на «Результат технічний», — это локальная заглушка «100 Вт/м²», которая выглядит как результат расчёта, но им не является.

### Причина блокировки

Автоматический расчёт запускается только когда выполнены **оба** условия:
1. у **каждой** комнаты заполнено «Площа, м²» (иначе запрос не уходит вообще, молча);
2. у **каждой** комнаты заполнена «Площа, м²» блока «**Стіна №1**» — отдельное поле, спрятанное ниже по карточке комнаты, ничем не помеченное как обязательное.

Поле «Стіна №1 → Площа, м²» — это тот самый барьер. Оно:
- не имеет ни звёздочки, ни слова «обов'язково», ни атрибута `required`;
- визуально выглядит как необязательная детализация (над ним стоит справочный блок «Зовнішні стіни (об'єкт)» с готовым описанием стены, что создаёт впечатление, будто стена уже задана);
- по умолчанию пустое, при этом соседнее «Висота, м» = `2.7` заполнено — это усиливает ощущение «остальное необязательно».

### Выход из блокировки (и вторая ловушка)

Как только у **всех** комнат заполнена «Площа», запрос начинает уходить — и приходит **400** с ошибкой, которая называет **только одну комнату за раз**:

- заполнили стену у Приміщення 1 → «Приміщення "Спальня" (r2): layout=facade вимагає одну фасадну стіну, отримано: 0.»
- заполнили стену у Приміщення 2 → «Приміщення "Санвузол" (r3): layout=facade вимагає одну фасадну стіну, отримано: 0.»
- заполнили стену у Приміщення 3 → расчёт прошёл (200), появились котёл/радиаторы/гидравлика.
- Скриншоты: `u3-exp5-blocked-400-facade-wall.jpg`, `u3-exp5-alert-closeup.jpg`, `u3-MAIN-repro-unblocked-after-3-walls.jpg`

То есть для дома на 8 комнат пользователь получит **8 последовательных ошибок подряд**, каждая — на языке разработчика (`layout=facade`), каждая — внизу страницы вне зоны видимости, без подсветки поля и без скролла к нему.

### Почему это и есть кейс владельца продукта

Эксперт-теплотехник заполняет то, что понимает как модель объекта: комнаты, площади, типы, людей. Поле «площадь наружной стены каждой комнаты» он либо считает выводимым (высота × периметр — система же знает площадь и высоту), либо просто не замечает. В этот момент система **не сообщает ничего** — просто подсовывает «швидку оцінку 100 Вт/м²» вместо расчёта. Никакого сигнала «расчёт не выполнен» на экране нет. Единственный (косвенный и молчаливый) признак — серая кнопка «PDF / Завантажити» в шапке без всякой подсказки.

## Эксперимент 2 — «минимальный обязательный набор»

**Метод:** заполнял поля по одному, после каждого проверял `browser_network_requests` на `POST /api/v1/calc`.

### Итог: минимальный набор для проекта из одной комнаты — **2 поля**

| # | Поле | Шаг | Проверка |
|---|---|---|---|
| 1 | «Площа, м²» приміщення | Приміщення → карточка комнаты | Только оно → запроса нет |
| 2 | «Площа, м²» блока «Стіна №1» | Приміщення → карточка комнаты, ниже | Только оно (без п.1) → запроса нет. Оба вместе → `POST /calc` 200 |

Проверено обеими сторонами:
- заполнил только «Площа, м²» комнаты, подождал, перешёл на «Результат» → **0 запросов**;
- чистая сессия, заполнил только площадь стены → подождал 3 с → **0 запросов**; добавил площадь комнаты → мгновенно `POST /calc` 200.

Для проекта из N комнат минимальный набор = **2N полей** (площадь комнаты + площадь стены №1 в каждой). Если у комнаты выбрано «Кутове / торцеве (дві зовнішні стіни)» — **3 поля** на комнату (появляется «Стіна №2»).

### Понятно ли ДО того, как упрёшься, что поле обязательное?

**Нет, ни по одному из блокирующих полей.**

- Ни у одного поля во всей анкете нет атрибута `required` (проверено через `browser_evaluate` на всех 11 шагах).
- Ни звёздочки `*`, ни подписи «обов'язково», ни цветового маркера, ни `aria-required`.
- Пустые поля визуально неотличимы от заполненных: у «Площа, м²» комнаты **нет даже плейсхолдера** — просто пустая рамка рядом с заполненной «Висота, м = 2.7».
- В левом меню шаги **никак не помечены** как незавершённые: у всех 11 кнопок один и тот же класс `_stepButton_...`, `disabled=false`, ни бейджей, ни галочек, ни счётчиков.
- В свёрнутой карточке комнаты незаполненная площадь показана как «`— м²`» — это единственный намёк, и он читается как «не указано», а не как «без этого расчёта не будет».

### Побочный, но важный факт

Все прочие поля анкеты (тип объекта, этажность, вентиляция, размещение котла, стена/утепление/кровля, режим ТП, температурный график котла, подводка и тип радиаторов, схема ГВП, тип разводки, длины труб, Δt) уже имеют валидные значения по умолчанию и **не блокируют** расчёт. Блокируют ровно два геометрических поля на комнату — и именно они не подсвечены.

## Эксперимент 3 — «пустые поля и плейсхолдеры»

Прочитаны фактические `value` / `placeholder` / `min` / `max` через `browser_evaluate` на шаге «Об'єкт».

### Таблица (шаг «Параметри об'єкта», чистая сессия)

| Поле | Что видно глазами | Реальный `value` | Реальный `placeholder` | `min`/`max` | Что уйдёт на сервер |
|---|---|---|---|---|---|
| «Всередині, °C» | `20` (обычный текст) | `"20"` | нет | нет / нет | `building.temps.insideC = 20` |
| «Зовні, °C» | `-5` (обычный текст) | `"-5"` | нет | **нет / нет** | `building.temps.outsideC = -5` |
| «Повітря в санвузлі, °C» | серое `≥24` | **`""` (пусто)** | `"≥24"` | `24` / `35` | **поле не отправляется вообще** — ключа `bathroomAirC` в payload нет |
| «Товщина несучої стіни, мм» | `300` чёрным | `"300"` | `"наприклад, 200"` | `50` / `2000` | `externalWalls.thicknessMm = 300` |
| «Кількість приміщень (1…50)» | `1` | `"1"` | нет | `1` / `50` | `objectMeta.roomsCount = 1` |
| «Площа, м²» (комната) | пусто | `""` | **нет** | `0.1` / нет | комната уходит **без** `areaM2` |
| «Висота, м» (комната) | `2.7` | `"2.7"` | нет | `1.8` / нет | `heightM = 2.7` |
| «Площа, м²» (Стіна №1) | пусто | `""` | `"наприклад, 20"` | `0` / нет | элемент `wall` **не создаётся** |
| «Ширина, мм» / «Висота, мм» (вікно) | пусто | `""` | **нет** | `200` / нет | окно **не создаётся** |
| «Кількість осіб» (ГВ) | `0` | `"0"` | нет | `0` / `20` | `hotWater.residents = 0` |

### Ответы на вопросы эксперимента

**Что уйдёт на сервер, если пользователь ничего не трогал?**
Ничего — запрос вообще не уходит (см. Эксп. 1/2). Как только расчёт всё-таки стартует, на сервер уходят реальные значения `insideC = 20`, `outsideC = -5`, `thicknessMm = 300`; `bathroomAirC` отсутствует; `residents = 0` и все девять точек водоразбора = `0`.

**Что произойдёт, если оставить «Повітря в санвузлі» пустым?**
Ничего плохого — поле просто не попадает в payload, сервер отвечает 200. Подпись под полем описывает это честно: «Порожньо = max(всередині, 24)». **Это единственное место во всей анкете, где поведение пустого поля объяснено пользователю.** Проверено и с комнатой типа «Санітарний вузол» — расчёт проходит.

**Где серое = подсказка, а где серое = значение?**
Единственный настоящий плейсхолдер, который можно спутать со значением, — `≥24` в «Повітря в санвузлі». Остальные серые «примеры» (`наприклад, 200`, `наприклад, 20`) стоят в полях, где либо есть реальное значение (`300` — чёрным), либо поле действительно пустое. Обратная и более опасная ситуация: **«Всередині 20» и «Зовні -5» выглядят как безобидные подсказки, но это реальные значения, которые молча уйдут в расчёт.** Никакой пометки «значення за замовчуванням» рядом нет.

### Три дефекта поведения значений

1. **Молчаливая коррекция ввода.** В «Повітря в санвузлі» ввёл `20` → поле само стало `24`. Ни сообщения, ни подсветки. Пользователь думает, что ввёл 20.
2. **Границы, о которых UI молчит.** У «Зовні, °C» нет `min`/`max` вообще, а сервер режет по `≤ 40` (см. Эксп. 5). У «Δt системи опалення» `max=30` есть в HTML, но при вводе не применяется — 50 вводится свободно и валится на сервере.
3. **Наблюдение без стабильного повтора:** в одной из сессий «Товщина несучої стіни, мм» посреди работы оказалась `200` вместо `300`, при том что пользователь её не трогал (значение совпало с текстом плейсхолдера `наприклад, 200`). Три попытки воспроизвести целенаправленно (в т.ч. через смену «Розташування приміщення») не удались. Фиксирую как незакрытое наблюдение — если подтвердится, это молчаливая подмена расчётного параметра ограждения.

## Эксперимент 4 — «навигация по левому меню»

**Можно ли прыгать по шагам произвольно?**
Да, полностью. Все 11 кнопок в `nav "Етапи анкети"` активны с первой секунды: `disabled = false` у всех, ни одна не заблокирована. Перейти с пустой анкеты сразу на «Результат технічний» или «Підсумок фінансовий» можно в один клик.

**Что происходит при переходе на «Результат технічний» с незаполненными шагами?**
Показывается **таблица нулей, оформленная как результат** (см. Эксп. 1). Не «заповніть анкету», не список недостающих данных — четыре строки с 0.0 и подпись «Джерело: швидка оцінка (100 Вт/м²)». Отличить это состояние от настоящего расчёта можно только по этой подписи: при успешном расчёте она меняется на «Джерело: розрахунок API за огородженнями» + появляется шапка «Підбір обладнання виконано за каталогом із бази даних (MongoDB)». **Разница между «не посчитано» и «посчитано» спрятана в одной строке мелким текстом.**

**Понятно ли, каких именно данных не хватает и куда идти?**
Нет. На «Результат технічний» — ни слова о недостающих данных. На «Підсумок фінансовий» — только «Заповніть анкету та дочекайтеся розрахунку» (какую часть анкеты — не сказано; и «дочекайтеся» вводит в заблуждение, потому что ждать нечего, запрос не отправлялся).
Единственная адресная подсказка во всей анкете — на шаге «Водонагрівач»: «На кроці «Гаряча вода» не задані мешканці та точки водорозбору...». Про блокирующие поля (площадь комнаты, площадь стены) не сказано **нигде**.

**Заблокированы ли шаги визуально?**
Нет. Ни блокировок, ни маркеров прогресса, ни отметок «заповнено / не заповнено», ни счётчиков ошибок в меню. Единственная разметка — `aria-current="step"` на активном шаге.

**Дополнительно.** URL не меняется при переходе между шагами (всегда `/`) — нет ни дип-линков на шаг, ни возврата по кнопке «Назад» браузера. Черновик сохраняется в `localStorage["heatcalc:survey-draft:v1"]` и после перезагрузки восстанавливается вместе с активным шагом — это работает корректно.

**Наблюдение с потерей данных на экране.** Проект из 3 комнат, где заполнена площадь только у комнаты 1 (20 м²): «Результат технічний» показывает «Загальна площа приміщень **0.0 м²**» — введённые 20 м² исчезают с экрана, а рядом «Потужність приміщень 0.2 кВт» осталась от прошлого расчёта. Скриншот: `u3-exp4-result-area-zero-3rooms.jpg`.

## Эксперимент 5 — «сообщения об ошибках»

### Как устроен показ ошибок

Единственный механизм: **один `<div role="alert">` в самом низу колонки контента**, ниже всех карточек текущего шага. Он:
- **не привязан к полю** — стоит в конце страницы, а не рядом с проблемным полем;
- **не скроллит к себе и не скроллит к полю**. Замер на шаге «Гідравліка»: поле Δt на `y ≈ 706`, алерт на `y ≈ 1047`, высота вьюпорта 728 — то есть в момент ввода алерт находится **за пределами экрана**, пользователь его физически не видит;
- **не подсвечивает поле**: `aria-invalid` не выставляется ни на одном инпуте (проверено `document.querySelectorAll('[aria-invalid="true"]')` → пусто);
- **исчезает после исправления** — это работает корректно;
- показывает **только одну ошибку за раз** (первую по порядку).

### Собранные ошибки (дословно)

| Провокация | Шаг | HTTP | Текст в UI (дословно) | Что реально вернул сервер |
|---|---|---|---|---|
| У комнаты не заполнена «Стіна №1 → Площа» | Приміщення | 400 | «Приміщення "Спальня" (r2): layout=facade вимагає одну фасадну стіну, отримано: 0.» | тот же текст, `code: ROOM_EXTERIOR_LAYOUT_WALLS` |
| «Кутове / торцеве» + заполнена только Стіна №1 | Приміщення | 400 | «Приміщення "Комната 1" (r1): layout=corner вимагає дві фасадні стіни, отримано: 1.» | тот же, `ROOM_EXTERIOR_LAYOUT_WALLS` |
| «Зовні, °C» = `50` | Об'єкт | 400 | «**Некоректні вхідні дані**» | `code: VALIDATION_ERROR`, `details: [{instancePath: "/building/temps/outsideC", keyword: "maximum", params: {limit: 40}, message: "must be <= 40"}]` |
| «Δt системи опалення (радіатори), K» = `50` | Гідравліка | 400 | «**Некоректні вхідні дані**» | `VALIDATION_ERROR` с `details` |

### Разбор по критериям

**Рядом с полем или в общем месте?** Всегда в общем месте — внизу страницы. Ни в одном случае ошибка не появилась около поля.

**На понятном ли языке?**
- `ROOM_EXTERIOR_LAYOUT_WALLS`: наполовину. Комната названа по имени и ID — это хорошо. Но «`layout=facade`» — это имя поля в коде, а не подпись из интерфейса («Розташування приміщення» → «На фасаді (одна зовнішня стіна)»). Пользователь должен догадаться о соответствии сам.
- `VALIDATION_ERROR` → «Некоректні вхідні дані»: **полностью непонятно**. Ни поля, ни шага, ни границы. При этом сервер прислал точный `details` с путём (`/building/temps/outsideC`) и правилом (`must be <= 40`) — **фронтенд эти данные получает и выбрасывает**. Пользователь на многошаговой анкете с ~40 полями получает «где-то что-то не так».

**Говорит ли, что именно исправить?** Первые два — да (нужна стена / нужны две стены), но не говорят, где это поле и как оно называется в UI. Последние два — нет вообще.

**Скроллит ли к полю?** Нет ни в одном случае.

**Исчезает ли после исправления?** Да, во всех случаях, сразу после успешного пересчёта.

### Кнопка расчёта и невалидные данные

**Отдельной кнопки расчёта в интерфейсе нет.** Расчёт автоматический (в текстах он назван «авторозрахунок»), дебаунс ~0.5 с после изменения поля. Следствия:
- при невалидных данных пользователю **некуда нажать**, чтобы получить обратную связь — нет действия, после которого система обязана отчитаться;
- при 400 экран результата **не очищается**: там остаётся результат прошлого успешного расчёта, а «Загальна площа приміщень» пересчитывается локально по новым данным. Получается гибрид: площадь новая (47.0 м²), мощность старая (0.2 кВт от расчёта на одну комнату). Скриншот `u3-exp5-result-stale-with-400.jpg`;
- **«Підсумок фінансовий» при активной ошибке 400 показывает полную смету** — «Загальна вартість об'єкта 143 342» — по устаревшему расчёту, с текстом ошибки одной строкой в самом низу под итоговой таблицей. Смету в этом состоянии можно выгрузить в PDF.

### Сырая техническая ошибка в таблице результатов

Режим «Опалення лише теплою підлогою» выбран, но галочка «Тепла підлога в цьому приміщенні» ни у одной комнаты не поставлена (она появляется в карточке комнаты **только после** выбора ТП-режима и по умолчанию выключена). Сервер отвечает 200, ошибок в UI нет, но в блоке «Гідравліка (підсумок)» в ячейку таблицы попадает строка:

> Труби — `ufh_only: обов'язковий circuits.underfloor.rooms`

Скриншот: `u3-exp5-ufh-only-raw-error-in-table.jpg`. Пользователю показан внутренний идентификатор поля API вместо объяснения «увімкніть теплу підлогу хоча б в одному приміщенні».

### Молча проглоченный ввод

Заполнил у окна только «Ширина, мм» = `1200`, «Висота, мм» оставил пустой. Сервер ответил 200. В payload (`u3-calc38-req.json`) в `envelopeElements` — только `wall` и `floor`, **элемента окна нет**. Ни предупреждения, ни пометки: введённые пользователем 1200 мм просто исчезли из расчёта. При этом карточка «Вікно 1» создаётся в каждой комнате **автоматически и пустой** — то есть по умолчанию каждая комната идёт в расчёт с окном-призраком, который не учитывается.

## Плейсхолдеры vs значения

| Поле | Шаг | Что видно глазами | Реальный `value` | Реальный `placeholder` | Что уйдёт на сервер |
|---|---|---|---|---|---|
| Всередині, °C | Об'єкт | `20` | `"20"` | — | `insideC: 20` |
| Зовні, °C | Об'єкт | `-5` | `"-5"` | — | `outsideC: -5` |
| Повітря в санвузлі, °C | Об'єкт | серое `≥24` | `""` | `≥24` | **ключ отсутствует в payload** (сервер применяет `max(inside, 24)`) |
| Товщина несучої стіни, мм | Об'єкт | `300` | `"300"` | `наприклад, 200` | `thicknessMm: 300` |
| Кількість приміщень | Об'єкт | `1` | `"1"` | — | `roomsCount: 1` |
| Назва (комната) | Приміщення | `Комната 1` (чёрным) | `"Комната 1"` | `Кімната 1` | `name: "Комната 1"` — **русское значение, украинский плейсхолдер** |
| Тип (комната) | Приміщення | `Приміщення` | `"помещение"` | — | `type: "помещение"` — **русские коды под украинскими подписями** |
| Площа, м² (комната) | Приміщення | пусто | `""` | **нет** | комната уходит **без** `areaM2` |
| Висота, м (комната) | Приміщення | `2.7` | `"2.7"` | — | `heightM: 2.7` |
| Площа, м² (Стіна №1) | Приміщення | пусто | `""` | `наприклад, 20` | элемент `wall` **не создаётся** → 400 |
| Ширина / Висота, мм (вікно) | Приміщення | пусто | `""` | **нет** | окно **не создаётся**; если заполнено только одно из двух — окно **молча выбрасывается** |
| К-сть однакових (вікно) | Приміщення | `1` | `"1"` | — | — |
| Кількість осіб | Гаряча вода | `0` | `"0"` | — | `residents: 0` |
| ГВ, °C (55…60) | Гаряча вода | `60` | `"60"` | — | `hotWaterC: 60` |
| Довжина магістралі, м | Гідравліка | `8` | `"8"` | — | `mainLineLengthM: 8` |
| Δt системи, K | Гідравліка | `20` | `"20"` | — | `deltaTSystemK: 20` |
| Підводи колектор → радіатор, м | Гідравліка | `4` | `"4"` | — | `pipeLengthToEquipmentM: 4` |

**Вывод по плейсхолдерам.** Классической ловушки «серая подсказка выглядит как значение» почти нет: единственный такой случай — `≥24`, и он единственный сопровождён честным объяснением. Настоящая проблема **обратная**: значения по умолчанию (`20`, `-5`, `300`, `2.7`, `8`, `20`, `4`, `0`) отрисованы как обычный пользовательский ввод и **никак не помечены как дефолтные**. Пользователь не может отличить «я это ввёл» от «это подставил сервис» — а именно эти цифры определяют расчётную нагрузку.

## Ошибки консоли и сети

### Консоль

За всю сессию — **только** повторы одной строки:

```
[ERROR] Failed to load resource: the server responded with a status of 400 ()
        @ https://heatcalc-api-mp62.onrender.com/api/v1/calc:0
```

Ни одного JS-исключения, ни одного React-warning, ни одного unhandled rejection. Приложение не падает — оно молчит.

### Сеть

| Запрос | Статус | Комментарий |
|---|---|---|
| `GET /api/v1/presets/envelope` | 200 | при старте |
| `GET /api/v1/presets/underfloor-heating` | 200 | при старте |
| `GET /api/v1/presets/underfloor-heating/modes` | 200 | при старте |
| `GET /api/v1/catalog` | 200 | при старте |
| `POST /api/v1/calc` | 200 / 400 | автоматический пересчёт на каждое изменение поля |

**Запросов дольше 3 секунд не зафиксировано.** 5xx не встретились ни разу.

**Все зафиксированные 4xx (с телом ответа):**

1. `{"ok":false,"error":{"message":"Приміщення \"Комната 2\" (r2): layout=facade вимагає одну фасадну стіну, отримано: 0.","code":"ROOM_EXTERIOR_LAYOUT_WALLS","statusCode":400}}`
2. `{"ok":false,"error":{"message":"Приміщення \"Комната 1\" (r1): layout=corner вимагає дві фасадні стіни, отримано: 1.","code":"ROOM_EXTERIOR_LAYOUT_WALLS","statusCode":400}}`
3. `{"ok":false,"error":{"message":"Некоректні вхідні дані","code":"VALIDATION_ERROR","statusCode":400,"details":[{"instancePath":"/building/temps/outsideC","schemaPath":"#/properties/building/properties/temps/properties/outsideC/maximum","keyword":"maximum","params":{"comparison":"<=","limit":40},"message":"must be <= 40"}]}}`
4. Аналогичный `VALIDATION_ERROR` для `deltaTSystemK = 50`.

**Ключевое по сети:** сервер отдаёт качественную адресную диагностику (`instancePath` + правило), а фронтенд показывает из неё только поле `message`. Массив `details` не используется — вся точность теряется на клиенте.

### Численные аномалии в успешных ответах (200)

Зафиксированы, поскольку напрямую бьют по доверию к «полученному расчёту»:

- При `residents: 0` и всех девяти точках водоразбора `= 0` в результате: «Потрібна потужність **24.00 кВт**», из них «на гарячу воду (ГВП): **24.00 кВт**», а «на опалення: 0.25 кВт». Подбирается БКН «30 л · OKH 100 NTR/HV · 95 л». То есть при нулевом потреблении ГВС система требует 24 кВт на ГВС и подбирает бойлер. Скриншот `u3-exp2-result-min-2fields.jpg`.
- Дом 600 м², наружная стена 1 м²: «Разом за теплом **0.2 кВт**» — никакой проверки правдоподобия (Вт/м²) нет.
- Дефолт комнаты противоречив: «Нижня межа» = «Знизу холод / підвал (стать)» (`unheated`), а «Підлога (огородження)» = «підлога — міжповерхове перекриття (квартира/сусіди)» — для объекта типа «Будинок, 1 поверх» это взаимоисключающие настройки, и обе стоят по умолчанию.
- Мощность 31.27 кВт → «Варіант 1 · економ: Baxi ECO Home 24 F · **24.0 кВт**» — предлагается котёл меньше требуемой мощности.

## Ранжированный список дефектов проходимости

**D1. Расчёт не запускается молча — без единого сообщения.** *(блокирующий, воспроизводится 100%)*
Пока хотя бы у одной комнаты пуста «Площа, м²», `POST /api/v1/calc` не отправляется вообще. Пользователь заполняет форму, ходит по шагам — и не получает ни ошибки, ни подсказки, ни индикатора. Это ядро сценария владельца продукта.
*Исправление:* при незаполненных обязательных полях показывать на «Результат технічний» список недостающих данных со ссылками на конкретные поля вместо таблицы нулей.

**D2. «Результат технічний» маскирует отсутствие расчёта под результат.** *(блокирующий)*
Экран показывает «Загальна площа / Потужність / Запас / Разом за теплом» с нулями и подписью «Джерело: швидка оцінка (100 Вт/м²)». Отличие от настоящего расчёта — одна строка мелким шрифтом. Пользователь уверен, что расчёт получен и он такой.
*Исправление:* заменить заглушку явным состоянием «Розрахунок ще не виконано» с перечнем причин.

**D3. Обязательные поля нигде не помечены.** *(блокирующий)*
Ни `required`, ни звёздочки, ни подписи, ни маркеров в левом меню, ни отметок завершённости шага. Два поля на комнату («Площа» комнаты и «Площа» стены №1) блокируют весь сервис и выглядят как необязательные — при том что «Висота, м» рядом уже заполнена.
*Исправление:* пометить обязательные поля, в левом меню показывать статус шага и число незаполненных обязательных полей.

**D4. «Некоректні вхідні дані» без указания поля — при том что сервер прислал точный адрес ошибки.** *(высокий)*
Ответ API содержит `details` с `instancePath: "/building/temps/outsideC"` и `message: "must be <= 40"`, но UI показывает только общую фразу. На анкете из 11 шагов пользователь не может найти проблему.
*Исправление:* маппить `details[].instancePath` на конкретное поле, показывать ошибку у поля и переходить на нужный шаг.

**D5. Ошибка показывается внизу страницы, по одной за раз, без скролла и без подсветки поля.** *(высокий)*
Замер: поле на `y ≈ 706`, алерт на `y ≈ 1047` при вьюпорте 728 — алерт вне экрана в момент ввода. `aria-invalid` не выставляется нигде. Для дома на 8 комнат — 8 последовательных ошибок «вимагає одну фасадну стіну», каждую надо ловить внизу страницы.
*Исправление:* показывать ошибку у поля + сводку всех проблем сразу, со скроллом к первой.

**D6. Устаревший результат и смета не очищаются при ошибке 400.** *(высокий, риск неверного коммерческого решения)*
При активной ошибке «Результат технічний» показывает смесь новых и старых чисел, а «Підсумок фінансовий» — полную смету («Загальна вартість об'єкта 143 342») по данным прошлого успешного расчёта. Кнопка «PDF / Завантажити» при этом активна — устаревшую смету можно выгрузить и отдать клиенту.
*Исправление:* при неуспешном пересчёте помечать результат как устаревший, блокировать экспорт.

**D7. Введённые данные молча выбрасываются.** *(высокий)*
Окно с заполненной шириной, но пустой высотой полностью исчезает из payload без предупреждения. «Повітря в санвузлі» = `20` молча превращается в `24`. Плюс каждая комната по умолчанию содержит пустую карточку «Вікно 1», которая никогда ни во что не превращается.
*Исправление:* валидировать частично заполненные группы полей, показывать факт коррекции значения.

**D8. Технические строки API в интерфейсе.** *(средний)*
«layout=facade вимагає одну фасадну стіну» и `ufh_only: обов'язковий circuits.underfloor.rooms` в ячейке таблицы результата. Пользователь видит имена полей API вместо подписей интерфейса.
*Исправление:* словарь «код API → подпись UI» на стороне фронтенда.

**D9. Кнопки действий заблокированы без объяснения.** *(средний)*
«PDF / Завантажити» — `disabled` без `title` и без текста рядом; это единственный (и молчаливый) индикатор того, что расчёта нет. «Зберегти» и «Посилання» имеют объяснение только в `title`, то есть только при наведении мышью — на тач-устройствах недоступно.
*Исправление:* показывать причину недоступности текстом.

**D10. Режим «лише теплою підлогою» приводит к сломанному результату без ошибки.** *(средний)*
Галочка ТП по комнатам по умолчанию выключена даже после выбора ТП-режима; сервер отвечает 200, а в результате — сырая строка ошибки в таблице труб.
*Исправление:* при выборе ТП-режима либо включать ТП во всех комнатах, либо блокировать расчёт с внятным сообщением.

**D11. Смесь языков и противоречивые дефолты в данных.** *(средний)*
На сервер уходят русские значения `name: "Комната 1"`, `type: "помещение"`, `construction: "наружная стена" / "пол"`, `name: "Пол"` под украинскими подписями UI (плейсхолдер при этом украинский — `Кімната 1`). Дефолт комнаты сам себе противоречит: «Знизу холод / підвал» + «підлога — міжповерхове перекриття (квартира/сусіди)» для одноэтажного дома.

**D12. Отсутствуют проверки правдоподобия результата.** *(средний)*
`residents = 0` → 24 кВт на ГВС и подбор БКН на 95 л. Дом 600 м² → 0.2 кВт теплопотерь. Требуется 31.27 кВт → предлагается котёл 24.0 кВт как «Варіант 1 · економ». Ни одного предупреждения о неправдоподобии.

**D13. Мелкие навигационные ограничения.** *(низкий)*
URL не меняется между шагами (нет дип-линков, кнопка «Назад» браузера уводит из приложения). Карточки комнат работают как аккордеон — одновременно открыта только одна, что при 8+ комнатах превращает заполнение в постоянное сворачивание/разворачивание. Незакрытое наблюдение: однократное самопроизвольное изменение «Товщина несучої стіни, мм» с 300 на 200 (повторить не удалось).
