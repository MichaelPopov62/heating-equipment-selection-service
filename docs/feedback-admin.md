# Административная панель обращений

Документ описывает доставку клиентских обращений из `POST /api/v1/feedback` в защищённую
административную панель. Web Push и WebSocket не используются.

## Поток данных

1. Клиент отправляет сообщение или отчёт об ошибке.
2. Backend валидирует тело и сохраняет документ `feedback` в MongoDB со статусом `new`.
3. После успешной записи backend публикует событие `feedback.created` в SSE-поток.
4. Открытая admin-страница получает событие, показывает уведомление и повторно загружает список.
5. После разрыва и восстановления SSE-соединения список также загружается повторно. MongoDB,
   а не поток событий, остаётся источником истины.

SSE-хаб хранится в памяти процесса. Для нескольких экземпляров API потребуется внешний
распределённый канал событий; REST-перезагрузка предотвращает потерю данных в интерфейсе,
но не гарантирует мгновенный toast между разными экземплярами.

## Доступ

Все административные маршруты требуют JWT и пользователя с `role=admin`:

- `GET /api/v1/admin/feedback`;
- `PATCH /api/v1/admin/feedback/:id`;
- `GET /api/v1/admin/feedback/stream`.

Frontend получает роль только из `GET /api/v1/me`. Проверка роли на клиенте скрывает интерфейс,
но не заменяет backend-авторизацию.

## Список и фильтры

`GET /api/v1/admin/feedback` принимает:

- `limit` — от 1 до 100;
- `cursor` — непрозрачный курсор следующей страницы;
- `status` — `new`, `read` или `resolved`;
- `type` — `bug` или `contact`.

Элементы возвращаются от новых к старым. `clientIp` не включается в административный DTO.

## Статусы

`PATCH /api/v1/admin/feedback/:id` принимает `{ "status": "..." }`.

- `new` очищает `readAt` и `resolvedAt`;
- `read` устанавливает `readAt` и очищает `resolvedAt`;
- `resolved` гарантирует `readAt` и устанавливает `resolvedAt`.

## Real-time

SSE-клиент использует потоковый `fetch` с заголовком `Authorization: Bearer ...`: стандартный
`EventSource` не позволяет передать Bearer-заголовок. Соединение закрывается через
`AbortController`, восстанавливается с задержкой и принимает heartbeat без обновления списка.

Уведомление доступно только при открытой административной панели. Уведомлений операционной
системы при закрытом браузере нет.

## Проверка

Минимальный smoke-сценарий:

1. Обычный пользователь получает `403` на admin API.
2. Администратор открывает `/admin/feedback` и видит сохранённые обращения.
3. Клиент отправляет feedback в другой вкладке.
4. В admin-панели появляется уведомление и новая строка без перезагрузки страницы.
5. Перевод в `read` и `resolved` обновляет даты и счётчик новых.
6. После отключения и восстановления сети список синхронизируется с MongoDB.
